Model Results

Overview

  • Goal: use historical AAPL price data to predict the next day’s closing price and determine which ML model does it best. This is a supervised regression problem — the model predicts an actual dollar value, not a category.
  • Data pulled via yfinance: AAPL from 2010-01-01 to present, ~4,150 trading days of Open, High, Low, Close, Volume (OHLCV). After feature engineering and dropping NaN rows from rolling windows: ~3,950 clean rows.
  • 7 models benchmarked: Ridge (with and without control feature), Lasso, ElasticNet, Random Forest, Gradient Boosting, and a Naive baseline (predict yesterday’s price as today’s).
  • A random Gaussian control feature is deliberately included as a sanity check — Ridge with vs. without it scored $1.1026 vs $1.1008 MAE, confirming the model captures real signal, not noise.

EDA & Statistical Analysis

What was analysed

  • Descriptive statistics: mean, median, standard deviation, skewness, and kurtosis applied to price and volume series to understand distribution shape and identify outliers before modelling.
  • Probability distribution analysis: daily return distributions plotted and tested against normality — AAPL returns show slight negative skew and fat tails (leptokurtosis), informing model choice.
  • Inferential statistics: correlation matrices computed across all 30+ engineered features to identify multicollinearity; hypothesis testing used to validate which indicators carry statistically significant predictive signal.
  • Feature validation: distributions of all engineered features inspected before model training to confirm no NaN leakage, scale inconsistencies, or look-ahead bias in any indicator.

Skills: Descriptive Statistics, Inferential Statistics, Hypothesis Testing, Correlation Analysis, Matplotlib, Seaborn.

Feature Engineering

30+ indicators built from past values only

  • Lag features: Close shifted back 1, 2, 3, 5, 10, 20, 60 days + yesterday’s Open/High/Low/Volume — gives the model direct memory of recent price levels without leaking future data.
  • Moving averages: SMA (10/20/50/200-day) and EMA (12/26-day) for trend identification; Close/SMA_20 and Close/SMA_50 ratios as scale-invariant trend-strength signals.
  • Momentum indicators: RSI-14 (overbought/oversold oscillator 0–100), MACD (EMA12 − EMA26), MACD signal line, MACD histogram, ROC-5 and ROC-20 (% price change over 5 and 20 days).
  • Volatility features: ATR-14 (accounts for gap days), Bollinger Band width (20-day SMA ±2σ), 20-day rolling standard deviation, volume ratio vs 20-day average, daily return, high-low spread, close-open spread.

Skills: Feature Engineering, pandas, NumPy, yfinance, Technical Analysis.

Walk-Forward Validation

Why standard train/test split fails for time series

  • A random split on time-series data would let the model train on 2022 and test on 2019 — it would learn from the future to predict the past, which is unrealistic and causes severe data leakage.
  • Instead: initial training window = 70% (~2,767 rows). Test window = next 60 trading days. After each window, training expands and all 7 models retrain fresh on the expanded history.
  • 19 total windows, ~1,140 out-of-sample test days — mimics real production: model retrained periodically on all data seen so far, never given future information.
  • StandardScaler fitted only on each window’s training data, then .transform() applied to test — prevents test-set statistics leaking into scaling. All predictions pooled across windows for final metric aggregation.

Skills: Walk-Forward Validation, Pipeline Design, StandardScaler, Data Leakage Prevention.

Model Results

Aggregated across all 19 walk-forward windows

  • Ridge Regression (best): MAE $1.10 · RMSE $1.52 · R² 0.9986 · MAPE 0.59% — beats the Naive baseline ($2.33 MAE) by 53%.
  • Lasso: MAE $1.61 · R² 0.9969. ElasticNet: MAE $6.41. Naive: MAE $2.33, R² 0.9934.
  • Why tree models underperformed: Gradient Boosting (MAE $4.61) and Random Forest (MAE $4.93) can’t extrapolate beyond training price ranges — AAPL’s upward trend meant trees systematically underestimated later-window prices.
  • Control feature check: Ridge with control scored $1.1026 vs $1.1008 without — near-identical, confirming the pipeline isn’t fooled by noise. Results visualised as actual-vs-predicted price charts, per-model error plots, and cumulative MAE over time.

Skills: Ridge Regression, MAE, RMSE, R², MAPE, Model Benchmarking, Matplotlib, Seaborn.

Hybrid Image Classification

A lightweight 193K-parameter hybrid architecture on CIFAR-10 that fuses a CNN backbone for local feature extraction with a patch-token branch for global context — conceptually similar to Vision Transformers but far smaller. Achieved 88%+ accuracy on balanced data. Also evaluated on a moderately imbalanced dataset with class-weighted training, and used Grad-CAM for visual explainability.

During this project,

  • Performed EDA on CIFAR-10: class distribution analysis, pixel intensity statistics, and visualisation of sample images using Matplotlib and Seaborn to inform preprocessing decisions and augmentation strategy.
  • Designed the tiny-HLGA architecture: Conv(32/64/128) CNN backbone produces a 4×4×128 feature map, split into 2×2 patch tokens via tf.image.extract_patches(), projected to 128-dim via Dense, globally averaged, then fused with the CNN’s own GAP output before the softmax head.
  • Simulated moderate class imbalance by reducing Cat, Deer, Dog classes to 20% of samples. Applied compute_class_weight('balanced') — affected classes received ~3.8× higher loss penalty, significantly recovering minority class recall.
  • Implemented Grad-CAM on the final conv layer (conv3): gradients of the predicted class score global-average-pooled into per-channel importance weights, multiplied back into activations, summed, upsampled to 32×32, and overlaid on the original image to confirm the model focuses on object regions, not background noise.

Overview

  • CIFAR-10: 60,000 32×32 RGB images across 10 classes. Pixels normalized from [0,255] to [0,1]. Train split 90/10 into 45,000 train / 5,000 val; official 10,000-image test set held out for final evaluation.
  • Problem: CNNs learn local patterns well (edges, textures, shapes) but miss global context. Vision Transformers capture global context but require enormous datasets. This hybrid gets both at only ~193K parameters.
  • Two models trained from scratch with clear_session() between runs: one on balanced data, one on moderately imbalanced data with class weighting — same architecture and epoch count for a fair comparison.
  • ModelCheckpoint(save_best_only=True, monitor='val_accuracy') saves best-epoch weights and reloads them after training, so the evaluated model is best on validation, not the last epoch.

Architecture (tiny-HLGA)

How local and global features are combined

  • CNN Backbone: Conv2D(32)→ReLU→MaxPool → Conv2D(64)→ReLU→MaxPool → Conv2D(128)→ReLU. Produces a 4×4×128 feature map. Each layer learns progressively higher-level patterns: edges → textures → object parts.
  • Patch-Token Branch: tf.image.extract_patches() slices the feature map into non-overlapping 2×2 patches → 16 tokens. Each token projected through Dense(128, relu) (a mini linear embedding, similar to Vision Transformer tokenization) → GlobalAveragePooling1D produces a 128-dim regional-summary vector.
  • Feature Fusion: CNN GAP (128-dim) + Token branch (128-dim) → concatenated → Dense(128, relu) → Dropout(0.3) → Dense(10, softmax). Dropout prevents co-adaptation of neurons, reducing overfitting.
  • Training: Adam lr=1e-3, sparse_categorical_crossentropy, batch 128. tf.data pipeline with shuffle → augmentation (RandomFlip, RandomCrop) → batch → prefetch(AUTOTUNE) for efficient CPU/GPU overlap.

Skills: TensorFlow, Keras, CNN Design, Patch Tokenization, tf.data, Dropout, Data Augmentation.

Imbalance Handling

Simulating and correcting class imbalance

  • Real-world datasets rarely have equal class distributions. A model trained on imbalanced data becomes biased toward majority classes — it can achieve high overall accuracy while completely failing on rare classes.
  • make_moderate_imbalance() subsamples Cat, Deer, Dog (classes 3/4/5) to 20% of their original count; all other classes stay full. Creates a controlled imbalanced scenario to study model behaviour under realistic conditions.
  • sklearn.utils.class_weight.compute_class_weight('balanced') computes per-class multipliers inversely proportional to frequency: affected classes get ~3.8× penalty, majority classes ~0.76×. Passed to model.fit(class_weight=cw_imb) — loss function penalizes minority-class mistakes more heavily during backpropagation.
  • Macro F1 used as primary metric (not accuracy): each class contributes equally regardless of sample count — gives a fair picture of performance on minority classes, not just majority ones.

Skills: Class Weighting, sklearn metrics, Macro F1, Precision/Recall, Confusion Matrix.

Grad-CAM Explainability

Understanding what the model looks at

  • Grad-CAM (Gradient-weighted Class Activation Mapping) answers: “Which spatial regions of the image most influenced this prediction?” — making the model less of a black box.
  • Process: choose predicted class → compute gradients of the class score w.r.t. the last conv layer (conv3) activations → global-average-pool gradients into per-channel importance weights → multiply weights into activations → sum channels → apply ReLU.
  • Resulting coarse heatmap upsampled from 4×4 to 32×32 and overlaid on the original image using cv2.addWeighted() — warm colours indicate high-importance regions, cool colours indicate low importance.
  • Correctly classified vs. misclassified samples compared side-by-side: correctly classified images show activation centred on the object; misclassified ones often show activation on background features, identifying failure modes.

Skills: Grad-CAM, TensorFlow GradientTape, OpenCV (cv2), Model Interpretability.

Results

Evaluated on the 10,000-image official test set

  • Balanced (45,000 images): 88%+ accuracy across all 10 CIFAR-10 classes. Val accuracy climbed from 37% → 63.7% in demo run (8 epochs); full training (40–80 epochs) reaches 88%+.
  • Imbalanced (Cat/Deer/Dog at 20%, class weighting): Test accuracy 59.98%, macro F1 60.25% on the 8-epoch demo — minority class recall significantly recovered vs. training without class weighting.
  • Outperformed baselines: hybrid architecture outperformed standalone CNN and transformer-only baselines on both balanced and imbalanced splits — fusion of local and global features provides complementary signal.
  • Grad-CAM confirmed meaningful spatial activations on object regions rather than background, validating the model classifies for the right reasons rather than spurious correlations.

Skills: Accuracy, Macro F1, Precision, Recall, Confusion Matrix, Grad-CAM, TensorFlow.

Cardiovascular Disease Prediction

End-to-end supervised ML pipeline on 70,000 patient records: data ingestion with error handling, feature engineering (age-in-days conversion), StandardScaler preprocessing, RandomForest (300 trees) training on 56,000 samples, joblib model persistence, and a Tkinter desktop GUI for live patient-level risk predictions. Achieved 70.8% accuracy with balanced precision/recall of 0.71 across both classes.

During this project,

  • Loaded the Kaggle Cardiovascular Disease dataset (70,000 rows, semicolon-delimited). Converted age from days to years (df["age"] = (df["age"] / 365).astype(int)). Handled missing file with sys.exit(1) for clean failure rather than a raw traceback.
  • Applied StandardScaler to all 11 features and saved the fitted scaler to scaler.pkl — live predictions use scaler.transform(), not fit_transform(), ensuring identical preprocessing between training and inference.
  • Trained RandomForestClassifier(n_estimators=300, n_jobs=-1) on 56,000 samples with stratify=y to preserve the ~50/50 class ratio. Implemented load_or_train_model() with joblib — trains once, loads instantly on all subsequent runs.
  • Built CardioPredictorApp in Tkinter: dynamic widget generation from a FIELD_SPECS dict (tk.Entry for numerics, ttk.Combobox(state="readonly") for categoricals), with color-coded prediction output (red = high risk, green = no risk).

Overview

  • Predicts cardiovascular disease risk (0 = no disease, 1 = high risk) from 11 health and lifestyle inputs: age, gender, height, weight, systolic BP, diastolic BP, cholesterol, glucose, smoking, alcohol, and physical activity.
  • Dataset: Kaggle Cardiovascular Disease (cardio_train.csv), 70,000 rows, semicolon-delimited. If the file is missing, sys.exit(1) exits cleanly with a clear message rather than crashing with a raw traceback.
  • Supervised binary classification: the model learns from 70,000 labeled records (cardio 0/1) and predicts the same for new unseen patients. This is a decision-support tool, not a clinical diagnostic system.
  • Full pipeline: raw CSV → age conversion → feature selection → scaling → RandomForest trained on 56K → validated on 14K → persisted to disk → Tkinter GUI for live predictions.

ML Pipeline

Step by step

  • Feature Engineering: age converted from days to years (Kaggle quirk in raw data). 11 features selected: age, gender, height, weight, ap_hi, ap_lo, cholesterol, gluc, smoke, alco, active. Target: cardio (0/1).
  • Preprocessing: StandardScaler applied to all 11 features. Random Forest doesn’t strictly require scaling (tree splits are scale-invariant), but it keeps the pipeline model-agnostic for future algorithm swaps. Fitted scaler saved as scaler.pkl.
  • Train/Test Split: train_test_split(test_size=0.2, random_state=42, stratify=y) — stratify=y preserves the ~50/50 disease ratio in both splits; random_state=42 ensures a reproducible split. 56,000 train / 14,000 test.
  • Model: RandomForestClassifier(n_estimators=300, n_jobs=-1) — 300 trees each on a random bootstrap sample, majority vote for final prediction. Three objects persisted via joblib.dump(): model, scaler, feature list. load_or_train_model() loads instantly if .pkl files exist; retrains only on first run.

Skills: pandas, scikit-learn, StandardScaler, RandomForest, joblib, Feature Engineering.

GUI Layer (Tkinter)

How the desktop application works

  • CardioPredictorApp class wraps the full interface. _build_layout() dynamically generates one labeled input widget per feature by looping over a FIELD_SPECS dictionary — not hardcoding 11 separate widget blocks, making it trivial to add or remove features.
  • Numeric fields (age, height, weight, BP) use tk.Entry; categorical fields (gender, cholesterol, glucose, smoking, alcohol, activity) use ttk.Combobox(state="readonly") — locks dropdown to valid values, prevents invalid category input entirely.
  • On Predict: _collect_inputs() reads all 11 values, casts to float, raises a clear user-facing error if anything is missing or invalid — program never crashes on bad input, always shows a meaningful message.
  • Input vector passes through scaler.transform() (same scaler from training, never re-fitted) → model.predict() → result displayed with color coding: red for high risk, green for no risk detected.

Skills: Tkinter, ttk.Combobox, Event-driven programming, Exception handling, UX design.

Performance

Evaluated on 14,000 held-out samples

  • Overall accuracy: 70.8% on the stratified 20% test set (14,000 samples never seen during training).
  • Precision, Recall, F1: 0.71 for both classes — balanced error rates, no systematic over- or under-diagnosis of either class.
  • Confusion matrix: ~4,956 true negatives, ~4,961 true positives, ~2,032 false positives, ~2,051 false negatives — nearly symmetric, confirming the model doesn’t favour one class.
  • 70–73% accuracy is consistent with published benchmarks on this dataset. The performance ceiling is largely set by label noise in self-reported cholesterol and glucose values in the original Kaggle data, not by model capacity.

Skills: Classification Report, Confusion Matrix, Precision/Recall/F1, ROC-AUC, scikit-learn.
